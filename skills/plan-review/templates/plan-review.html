Plan summary

In plain terms

Switching login from cookie sessions to JWTs. Faster sign-in and works across subdomains, but if it breaks nobody can log in until you roll back. Plan proposes a feature flag — a switch you can flip to turn it off without a deploy — as the safety net.

The intuition

Today, every authenticated request hits the sessions table to verify the cookie. That's a DB read per request. JWTs carry their own proof of identity, so the server can verify without touching the DB. Trade-off: revoking a stolen token is harder.

5. Change-by-change

#1 app/auth/login.tsx Rewrite session handler to use JWT UX

Current

function createSession() {
  cookie('sess', token, {
    httpOnly: true
  })
}

Planned

function createSession(ctx: AuthCtx) {
  return jwt.sign(ctx, KEY, {
    expiresIn: '30d'
  })
}
In plain terms

Switching from cookies to JWTs (a signed token the browser carries). Means logins work across subdomains without extra setup, but harder to revoke a stolen token. Plan adds a "remember me" checkbox to extend sessions from 1 day to 30.
